# Transactional storage and telemetry

Select `OAUTH2_STORAGE=sqlite|postgres|mongo` (SQLite is the default). Set `OAUTH2_DATABASE_URL` to a PostgreSQL or MongoDB connection string for network backends; do not log or commit that value. Keep signing-key persistence and backups managed separately. PostgreSQL initializes `oauth2_documents` and uses a transaction-scoped advisory lock per namespace; MongoDB requires a replica set (including a single-node test replica set) and retries write conflicts on a shared transactional guard. Standalone MongoDB is refused. Each store enforces single-use code, PAR, device and DPoP claims and refresh-family replay revocation within a database transaction, including across server processes. Root operations also run transactionally. A transaction callback can be retried by the MongoDB driver: do not perform external side effects in it. The generic document-backed adapters scan token families and client-issued records, so profile real workloads before treating them as high-throughput replacements for SQLite.

For local parity tests, start disposable PostgreSQL and MongoDB replica-set instances and run `TEST_POSTGRES_URL=... TEST_MONGO_URL=... bash scripts/test-adapters.sh`. CI provisions both and executes the same real-database tests, including restart, rollback and competing consumers. The SUT conformance seed is intentionally restricted to in-memory SQLite and refuses a network store.

`OAUTH2_METRICS_ENABLED=1` exposes `GET /metrics` only when `OAUTH2_HOST` is loopback. It emits Prometheus text counters and latency buckets labeled solely by fixed operation and response class; no client IDs, arbitrary paths, tokens or usernames. Put an authenticated proxy in front of metrics if exporting remotely. Applications embedding `buildServer` can supply an optional `trace(name)` callback that returns a span-ending function; names are fixed `oauth.http.<operation>` values with no dynamic attributes. Neither an exporter nor a tracing backend is bundled. Counters reset on process restart.
